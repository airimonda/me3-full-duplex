SYSTEM DIAGRAM

the one diagram that explains the build
mic → VAD (RPi) → ASR (Deepgram) → agent + tools (RPi) → LLM (cloud) → TTS (Deepgram) → speaker
barge-in: owner voice + stop word → flush TTS + drop LLM stream → listen
  • Mic → VAD on the RPi → Deepgram ASR (nova-3, live websocket fed while the user talks) → agent on the RPi → Deepgram TTS (Aura-2 Jupiter, audio played as it streams in) → speaker on the RPi.
  • Harness: Pipecat 1.15, one FrameProcessor (WatsonAgent). Stock transports only; the same agent runs the live mic and the benchmark socket.
  • LLM: z-ai/glm-5.3-flash via OpenRouter, streaming with function calling. 20 s read timeout; an empty stream goes straight to gpt-4o-mini. Tool turns say "One sec." while the tool runs.
  • Task MCP on the RPi: tasks_mcp.py (streamable HTTP) takes big jobs and web lookups. Jobs run the pi.dev agent under bubblewrap, writing only in ~/sandbox; the Watson UI (ui_server.py, also on the Pi) serves the result and the Mac opens it; Watson announces it at the next pause, never reading a path.
  • Deviation from the brief: ASR and TTS are commercial APIs (Deepgram) called directly from the RPi, not through our own MCP servers. Quick tools (lights, timers) are in-process calls. The Mac's Whisper/Kokoro server stays as a fallback.
  • Second MCP built by us: tts_mcp.py (EfficientSpeech Tiny, tools speak, health). Tested on the Mac; not in the live loop.
  • Barge-in cancels playback (InterruptionFrame) and the LLM stream (generation counter). The unplayed audio is stashed so a "yeah" backchannel can resume it.
  • Boundary: RPi = audio I/O, VAD, gates, agent loop, tools, task MCP + pi.dev agent, Watson UI. Mac = benchmark harness, result viewer, fallback ASR/TTS. Cloud = Deepgram, LLM, search engine.

PROMPT

in the repo, versioned: brain.py v4 (Nov 6, owner-approved)
SYSTEM PROMPT (brain.py v4) · full text, verbatim

You are Watson, a voice assistant in a live spoken conversation. Reply in one or two short spoken sentences, plain text, no markdown or emoji; give more detail only when asked.

When a request is clear, act with the right tool without offering first. If a needed detail is missing, ask one short question.

Handle music, lights, thermostat, timers, alarms, reminders and messages yourself with their tools.

Say an action is done only after the tool confirms it; say clearly if it is pending or failed.

For news, facts you are unsure of, and the time in other cities, use web_search; never guess. If the search doesn't settle it, say so briefly.

Never mention tools or internal details.

After an interruption, follow the user's latest request; an action already submitted still stands unless they cancel it.

Big jobs (sites, apps, research, files) go to the background agent: reply DELEGATE: <one-line request>. Never speak the tag. If the job has no topic yet ("build me a website"), ask what it should be about first.

Owner-approved v4 (lines 1–7). The last line (teal) is the runtime DELEGATE protocol the voice loop parses. Barge-in is enforced in code; a filter strips paths, file names and URLs from everything Watson says. Bench mode appends an addressed-speech rule and a 35-word cap.

CONTEXT ENGINEERING

GOES IN:

  • System prompt v4 (~230 tokens) + 10 tool schemas (~780 tokens)
  • Final Deepgram transcript per turn, wake word stripped (no partials)
  • Tool results as tool messages, for that turn only
  • Conversation history (rolling)
  • VAD turn events drive the loop; they stay out of the context
  • Memory: in-conversation only, no RAG

MANAGED:

  • History capped at the last 12 messages, cut at a user turn so no tool reply loses its call
  • Why: the first token arrives later as the context grows
  • Tool calls and results dropped once the turn is answered
  • idle (5 min) → listen → think → speak
  • On barge-in: generation++, stale audio and stream dropped
  • Measured (fdbench): 1,665 prompt tokens per call median (max 2,107), 12 messages (max 15)

standardized latency method

DEMO (run sheet: docs/demo-spiel.html)

  1. "Watson" → "Yes? I'm listening." (also "button", "Hudson")
  2. "Build me a website about Manila street food" → task MCP, pi.dev
  3. Meanwhile: "Who won the 2026 NBA finals?" → spoken answer
  4. Meanwhile: "Lights off" → lights_control
  5. "Done! The ... website is ready" → page opens by itself
  6. "Stop" → barge-in; classmate says "Watson, …" → takes over
No push-to-talk. Slow API: 20 s timeout; an empty reply goes to gpt-4o-mini.

CHALLENGES & REFERENCES

  2. Accent: "Watson" heard as "button", "Hudson" → high-recall wake matcher; caught wakes in the logs 81 → 87, no new false wakes; 74/74 tests.
